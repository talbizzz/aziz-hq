# Manual migrations

Declarative schemas in `supabase/schemas/` are the source of truth, but the diff tool does not track DML, publication membership, or grants on some objects. Every hand-written migration in `supabase/migrations/` must be listed here, or the drift check fails.

| Migration                                       | Reason                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `20261105110800_realtime_publication.sql`       | Publication membership (`supabase_realtime`: runs, tasks, gates, events, worker_heartbeats) and the `factory` module row are not tracked by the diff tool (ADR-4).                                                                                                                                                                            |
| `20261105110810_lock_down_table_privileges.sql` | Default privileges give `anon`/`authenticated` TRUNCATE, REFERENCES, TRIGGER and MAINTAIN on new public tables, and the diff tool does not emit REVOKEs. Revokes them on existing tables and removes the default ACL for future ones, and removes PUBLIC's default EXECUTE on future functions. Mirrored in `supabase/schemas/15_grants.sql`. |
| `20261105142900_settings_defaults.sql`          | Default settings rows (timezone, quiet hours, digest time, worker-offline threshold) are DML, not tracked by the diff tool. Idempotent (`on conflict do nothing`).                                                                                                                                                                            |
| `20261105143000_telegram_cron_jobs.sql`         | The two `pg_cron` jobs (`flush_notifications` every minute, `worker_watchdog` every 3 minutes) are data in `cron.job`; not tracked by the diff tool. Idempotent (`cron.schedule` upserts by name).                                                                                                                                            |
