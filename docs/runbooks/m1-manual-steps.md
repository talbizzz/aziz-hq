# Milestone 1: steps only the owner can do

The code, workflows and scripts for these are in the repo; each step needs an account or a decision that an agent must not take alone. Do them in order; the first column is the milestone task they unblock.

| Task  | Step                                                                                                                                                                                                                                                                                 |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T1.3  | Protect `main`: Settings > Branches (or `gh api`): require a pull request, require the checks `typecheck, lint, test`, `gitleaks`, `database (pgTAP, drift, types)` and `web (e2e)`, block force pushes. Re-check the repo's private visibility.                                     |
| T1.9  | Create the Supabase project `aziz-hq-platform` in the personal account (region Frankfurt, strong DB password in the password manager). In its dashboard: disable email sign-ups, enable TOTP MFA, set the Site URL to `https://hq.aziztalbi.com`.                                    |
| T1.9  | GitHub secrets (environment `production`): `SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF`, `SUPABASE_DB_URL` (Connect > Session pooler URI, with the password percent-encoded; its user must be `postgres.<ref>`). Variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`. |
| T1.9  | First push, from your machine: `SUPABASE_PROJECT_REF=... SUPABASE_DB_URL=... pnpm db:push` (dry run), then `CONFIRM=1 pnpm db:push`. Then `pnpm tsx scripts/verify-hosted.ts` with the two `VITE_` variables.                                                                        |
| T1.9  | Create the owner from your shell (service-role key only in your environment): `SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... OWNER_EMAIL=... OWNER_PASSWORD=... pnpm create-owner`.                                                                                                 |
| T1.11 | Follow `docs/runbooks/cloudflare-access.md`. Then set the repo variable `DEPLOY_ENABLED=true` so `deploy.yml` runs after CI.                                                                                                                                                         |
| T1.12 | Run the keepalive workflow once by hand (Actions > Keepalive > Run workflow).                                                                                                                                                                                                        |
